4 histórias reais — o que muda na prática

1
DataBricks

"Saio de uma reunião, despacho 2–3 cloud agents. Volto da próxima reunião e têm PRs esperando por mim."

Intervalos entre reuniões → onde mais código avança
2
Cursor — Projetos

Projeto → Partes → Feature full-stack por parte → Tasks no tamanho certo. Cada feature dispara ~5 cloud agents simultâneos.

Coordenação mudou de objeto: de devs para agentes
3
Cursor — Dados

"Quantos usuários teriam mais de X itens?" — MCP vai ao banco, traz o número. Arquitetura decidida antes de escrever uma linha.

O agente vira pesquisador. O dev, decisor.
4
Cursor — Bug

"DataDog + Audit Logs + GitHub — cria uma timeline." Um prompt. Diagrama em minutos. PR culpado identificado.

Post-mortem de 1 dia → investigação em minutos

🤔 A pergunta que todo mundo faz

"ain Victor, mas eu não sei usar a IA"

🤦 Jeito errado
user: cria um sistema de autenticação
user: resolve esse bug
user: faz um CRUD
← sem contexto, sem tech, sem spec
✕ Pedido vago → resultado genérico
✕ Sem contexto → código que não encaixa
✕ Sem revisão → aceita tudo sem testar
Resultado: "a IA não presta"
✅ Jeito certo
📋 Planejamento
Defina o objetivo, quebre em partes, use EnterPlanMode antes de codar.
📎 Contexto
Dê o código relevante, as regras do projeto, a tecnologia, as restrições. A IA trabalha com o que você dá.
👀 Revisão
Leia o que foi gerado. Teste. Dê feedback. Itere. Você é o decisor — a IA é o executor.
